# 数据库查看与演示命令

适用环境：Windows PowerShell，容器 `herbmind-v2-pg`，数据库 `herbmind`。

## 0. 连接信息

| 项 | 值 |
|---|---|
| 容器 | `herbmind-v2-pg` |
| 镜像 | `pgvector/pgvector:pg17`（PostgreSQL 17） |
| 地址 | `localhost:5432` |
| 数据库 | `herbmind` |
| 账号 / 口令 | `postgres / postgres` |
| 新库模式 | `public`（30 张表） |
| 旧库模式 | `legacy`（41 张表，保留旧数据） |

GUI（DBeaver / Navicat）按上表填即可。用 psql 进入：

```powershell
docker exec -it herbmind-v2-pg psql -U postgres -d herbmind
```

退出：`\q`

## 1. 先分清 public 与 legacy

```sql
-- 两个模式各有多少张表
select table_schema, count(*) as tables
from information_schema.tables
where table_schema in ('public','legacy')
group by table_schema
order by table_schema;

-- 新库 30 张
\dt public.*

-- 旧库 41 张
\dt legacy.*
```

判别点：

```sql
-- 新库没有 search_tsv，返回 0
select count(*) from information_schema.columns
where table_schema='public' and table_name='content_unit' and column_name='search_tsv';

-- 旧库有 search_tsv，返回 1
select count(*) from information_schema.columns
where table_schema='legacy' and table_name='content_unit' and column_name='search_tsv';
```

应用连接不写模式名时走 `public`，所以默认看到的是新库；旧数据要显式写 `legacy.`。

## 2. 看结构

```sql
-- 表结构（字段、类型、可空、默认）
\d public.content_unit
\d public.question
\d public.data_defect

-- 某张表的约束（主键、外键、CHECK、唯一）
select conname, contype, pg_get_constraintdef(oid) as definition
from pg_constraint
where conrelid = 'public.content_unit'::regclass
order by contype, conname;

-- 某张表的索引
select indexname, indexdef
from pg_indexes
where schemaname='public' and tablename='content_unit'
order by indexname;

-- 全部外键与级联策略（confdeltype: r=RESTRICT, c=CASCADE）
select conname, confdeltype,
       conrelid::regclass as child_table,
       confrelid::regclass as parent_table
from pg_constraint
where contype='f'
  and conrelid::regclass::text like 'public.%'
order by child_table, conname;
```

## 3. 看数据

新库目前只有题型白名单，业务数据等新导入链写入：

```sql
select code, name, enabled from public.question_type order by code;

-- 新库业务表当前为空，属预期
select count(*) as books from public.book;
select count(*) as units from public.content_unit;
```

旧数据在 `legacy`，用于对照与演示：

```sql
select 'book' as table_name, count(*) from legacy.book
union all select 'content_unit', count(*) from legacy.content_unit
union all select 'formula', count(*) from legacy.formula
union all select 'formula_herb', count(*) from legacy.formula_herb
union all select 'case_record', count(*) from legacy.case_record
union all select 'book_node', count(*) from legacy.book_node;

-- 旧库书目与单元数
select b.title, count(u.id) as units
from legacy.book b
left join legacy.content_unit u on u.book_id = b.id
group by b.title;

-- 旧库组成最多的方
select f.name, count(fh.id) as herbs
from legacy.formula f
join legacy.formula_herb fh on fh.formula_id = f.id
group by f.name
order by herbs desc, f.name
limit 10;
```

## 4. 一键核对（演示时先跑这个）

```sql
select 'public_tables' as item, count(*)::text as value
  from information_schema.tables where table_schema='public'
union all select 'legacy_tables', count(*)::text
  from information_schema.tables where table_schema='legacy'
union all select 'public_fks', count(*)::text
  from pg_constraint c
  join pg_class t on t.oid=c.conrelid
  join pg_namespace n on n.oid=t.relnamespace
  where n.nspname='public' and c.contype='f'
union all select 'public_cascade_fks', count(*)::text
  from pg_constraint c
  join pg_class t on t.oid=c.conrelid
  join pg_namespace n on n.oid=t.relnamespace
  where n.nspname='public' and c.contype='f' and c.confdeltype='c'
union all select 'question_types', count(*)::text from public.question_type
union all select 'public_search_tsv_cols', count(*)::text
  from information_schema.columns
  where table_schema='public' and table_name='content_unit' and column_name='search_tsv'
union all select 'legacy_content_units', count(*)::text from legacy.content_unit
union all select 'legacy_formulas', count(*)::text from legacy.formula;
```

预期：`public_tables=30`、`legacy_tables=41`、`public_fks=38`、`public_cascade_fks=7`、`question_types=3`、`public_search_tsv_cols=0`、`legacy_content_units=598`、`legacy_formulas=245`。

## 6. 备份与恢复

备份整个库：

```powershell
docker exec herbmind-v2-pg pg_dump -U postgres -d herbmind --no-owner --no-acl -Fc -f /tmp/herbmind_backup.dump
docker cp herbmind-v2-pg:/tmp/herbmind_backup.dump database\backup\
```

恢复到临时库（验证备份可用）：

```powershell
docker exec herbmind-v2-pg createdb -U postgres herbmind_restore
docker cp database\backup\herbmind_backup.dump herbmind-v2-pg:/tmp/herbmind_backup.dump
docker exec herbmind-v2-pg pg_restore -U postgres -d herbmind_restore /tmp/herbmind_backup.dump
docker exec herbmind-v2-pg psql -U postgres -d herbmind_restore -c "select count(*) from public.question_type;"
docker exec herbmind-v2-pg dropdb -U postgres herbmind_restore
```

## 8. 常见问题

| 现象 | 原因与处理 |
|---|---|
| `\dt` 只看到 30 张 | 默认 `search_path=public`，旧表在 `legacy`，需写 `\dt legacy.*` |
| 新库查询都是 0 行 | 新库尚未导入内容；旧数据在 `legacy`，属预期 |
| 提示 `search_tsv` 不存在 | 新库按设计不建该列；旧库 `legacy.content_unit` 才有 |
| 端口 55432 连不上 | 那是已删除的分词实验容器，现只保留 5432 |
| 想改表结构 | 不要直接改库；改 `06`，新增 `V2__xxx.sql`，再迁移 |

## 9. 不要做的事

- 不要删 `herbmind-v2_pgdata` 卷，新库在里面。
- 不要执行 `docker compose down -v`，会连同数据卷一起删。
- 不要直接 `DROP` 或 `ALTER` 新表来试字段；用事务或临时库验证。
