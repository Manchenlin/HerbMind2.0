## 三处主动取舍

| 取舍 | 理由 |
|---|---|
| 练习只做选择题 / 组成匹配 / 类方比较，默写与条文补全延期 | 自由文本逐字判定做不准会把对的判错，首版不承担 |
| 系统只做窄原型（导入链 + 检索 + 出处） | 16 天、有效人力 1.5 人；练习与解释可在原型上续补 |
| 不承诺教材或考纲口径 | 无专家审核，只能承诺可回溯原文，不承诺覆盖考点 |

## 三条红线（被问"为什么不做成通用问答"时用）

1. 只查证 + 引用，不推断功效、不推演证治。
2. 查不到就说查不到，不用"一般来说""临床上多用于"这类无出处表述。
3. 不给处方与剂量建议；原文与医案中的剂量按史料呈现，系统不生成、不推荐、不换算。

## 预备答问

| 可能的问题 | 回答要点 |
|---|---|
| 为什么不用大模型直接问答？ | 无出处不可核。本项目信任来源只有原文，生成内容无法逐句对应到库内片段，因此默认关闭；开启后也受四类约束（来源、引用、拒答、范围）。 |
| 16 天做得出系统吗？ | 只做窄原型：导入一本书 → 检索 → 看到出处。不做练习与解释。实现在既有代码上改造，不重写。 |
| 内容有版权吗？ | 用教学整理本，授权已确认；只取标注为"典籍原文"的段落，不复制其注释与论述。 |
| 三个人怎么分工？ | 见上表。有效人力按 1.5 人估，不按 3 人估，排期已按此做过压缩。 |
| 怎么保证文档和系统一致？ | 单向改造（文档 → 实现）、实施前出差距清单、追踪矩阵四段（需求→设计→实现→测试）不缺；一致性检查列为测试验收项。 |
