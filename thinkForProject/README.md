# HerbMind 软件工程课程项目工作区

> 本目录用于从《软件工程导论》课程视角，对 HerbMind 中医经典学习平台进行重新分析、建模与设计。
>
> 本工作区**不以现有代码为实现依据**。现有代码只说明系统曾经怎样被实现，不能替代需求、分析、设计和论证。

## 1. 工作目标

产出一套结构完整、前后一致、可追溯的软件工程课程文档，覆盖：

- 问题定义、项目背景与可行性研究
- 需求获取、需求分析与软件需求规格说明
- 面向对象分析与 UML 建模
- 体系结构、模块、接口、数据和界面设计
- 项目进度、风险、配置与质量管理
- 测试策略、测试用例与验收标准
- 用户手册、答辩材料和演示脚本

## 2. 目录职责

## 3. 每次开始工作时的阅读顺序

1. 本文件：确认目录职责和边界。
2. `plan/00_全局记忆.md`：确认当前阶段、已确认决定、假设和未决问题。
3. `plan/01_总体计划.md`：确认下一步任务与评审关口。
4. 最近一次 `track/00_决策与工作日志.md`：确认上轮工作发生了什么。
5. 需要写作时再看 `plan/02_文档规范.md` 和 `docs/00_文档索引.md`。

## 4. 信息优先级

发生冲突时按以下顺序处理：

1. 用户最新且明确的指示。
2. `plan/00_全局记忆.md` 中已确认的决定。
3. `docs/` 中已经通过评审的正式文档。
4. `track/` 中的过程记录和草稿。
5. 尚未确认的假设。

发现冲突时不要自行掩盖，应在 `track/00_决策与工作日志.md` 记录冲突，并请用户裁决。

## 6. 范围边界

### 纳入分析

- 中医经典与方证的阅读、检索、学习和复习
- 方剂、药味、医案、条文之间的内容关系
- 知识图谱、问答、练习、笔记、收藏和错题等学习支持
- 内容导入、内容治理和系统运维等后台能力
- 用户、权限、安全、性能、可用性和可维护性等非功能需求

### 不作为系统目标

- 替代医生进行诊断、处方或剂量建议
- 面向医院的挂号、收费、电子病历等业务系统
- 在没有出处的情况下推断功效、证治或生成新方
- 用当前代码的技术选型反过来限制课程阶段的需求与设计

## 7. 写作边界

- 正式文档使用中文，采用规范、克制、可验证的软件工程表述。
- 不写“AI 自动生成”“本回答”“根据代码推测”等实现或对话痕迹。
- 事实、决定、假设和待确认内容必须区分，不得用印象补全。
- 需求、设计、测试之间必须建立编号和追踪关系。
- 设计红线继续有效：只查证和引用，不提供诊疗建议，不生成处方或剂量。
- 未经用户明确要求，不为这个课程任务修改业务代码。

### 讨论与质疑规则

- 讨论双方都可以提问、质疑、反驳或提出不同见解，不要求表面一致。
- 任何意见、质疑或反驳都必须说明依据：事实来源、推理过程、影响范围或可验证的替代方案。
- 证据不足时必须明确说“不确定”并标为假设，不能用印象、语气或身份替代论证。
- 可以指出对方论证中的漏洞，但必须说明“针对哪条判断、为什么有问题、会导致什么后果”。
- 用户拥有最终决定权；助手有义务在用户决定前说明已知风险和不同方案，而不是事后附和。
