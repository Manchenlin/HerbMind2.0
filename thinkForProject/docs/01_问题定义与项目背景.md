## 1. 文档信息

### 1.1 目的

本文档定义本系统要解决的问题、服务对象、现有方式的局限、优化机会、成功标准与范围边界。它是可行性研究、需求规格与后续设计的输入基线。

本文档不讨论实现方案，不比较技术选型，不给出功能清单。

### 1.2 范围

覆盖：项目背景与领域情境、目标用户与干系人、问题陈述、现有方式局限、问题优先级、优化机会初筛、项目愿景与成功标准、系统范围与非目标、约束与假设。

不覆盖：候选方案比较、技术与经济可行性、功能需求编号、界面与数据结构设计。

### 1.3 读者对象

课程指导教师与评审、项目组成员、后续阶段的文档编写者、内容维护者。

### 1.4 术语与缩略语

| 术语 | 说明 |
|---|---|
| 典籍原文 | 中医经典著作的正文文本，是系统内一切解释与判定的最终依据 |
| 条文 | 典籍原文中可独立引用的最小文本单元，通常以句为界 |
| 方剂 | 有固定名称与药味组成的处方记录 |
| 药味 | 方剂组成中的单味药 |
| 医案 | 记载诊疗过程的原始记录，含症状、方药与经过 |
| 方证关系 | 方剂与所对应证候、条文之间的对应关系，本系统中作为可检索的既有记录，不作为推理结论 |
| 出处块 | 系统在输出内容旁统一呈现的定位信息，含书名、篇名、条号（可得时）与原文片段 |
| 内容单元 | 系统内可检索、可引用、可定位的最小内容记录 |
| 机判题型 | 答案可依据库内结构化数据自动判定对错的练习题型 |
| 拒答 | 系统在库内找不到可引用依据时，不生成解释而返回提示的行为 |
| 底本 | 导入系统时所依据的具体出版物或整理文本 |
| 定位字段 | 用于标明内容单元来源的字段集合，含书名、版本、篇名、条号 |

## 2. 项目背景与领域情境

### 2.1 领域情境

中医经典课程是中医学本科教育的法定组成部分。据教育部与国家中医药管理局公开答复，2018 年《普通高等学校本科中医学类教学质量国家标准》要求在课程计划中开设《黄帝内经》《伤寒杂病论》《金匮要略》《温病学》等经典课程；对全国 53 所开设本科中医学专业院校的调研显示，必修课总学时平均 2803 学时，其中中医类课程 1228 学时（约 44%），西医类课程 776 学时（约 28%），四门经典课程平均 268 学时，约占中医类必修课的 22%、全部必修课总学时的 10% `[事实]`（REF-01、REF-02，数值待正式核对）。

由此得到两条与本研究直接相关的事实：

1. 经典课程有稳定的课程范围与考核要求，学习目标由外部给定，不需要产品替用户定义“学什么算学会”。
2. 经典课程在培养体系中约占 10% 的学时，本系统的定位只能是**经典学习的专用工具**，不能表述为覆盖中医学全部课程的学习平台。

### 2.2 经典学习的任务特征

经典学习与一般阅读的差别在于四类任务同时存在：

| 任务 | 表现 | 对工具的依赖 |
|---|---|---|
| 读原文 | 文言与古奥术语，需要反复回看上下文 | 排版、定位、跨条文对照 |
| 核组成 | 同一方名在不同典籍中的组成记载需要比对 | 按方名与药味双向检索 |
| 找出处 | 引用需要精确到书、篇、条 | 出处可核、可回溯 |
| 验掌握 | 需要自测条文记忆与方证对应 | 可判定的练习与错题回流 |

单一阅读器只能覆盖第一项，通用检索只能覆盖第二项的一部分，AI 助手若不给依据则第三项失守。这是本项目的立足点。

### 2.3 与本工作区其他资料的关系

本文档的问题与目标为唯一权威表述，`docs/02` 及之后各文档引用本文档，不重新定义问题。

## 3. 目标用户与干系人

### 3.1 主要用户

> 正在系统学习中医经典、或以经典能力考试为目标的课程学习者。

选择依据：其学习任务、内容范围与验收方式均由外部（课程与考试）给定，产品无需自行定义学习路径；相较自学者，需求边界更清晰，问题更容易收敛。

### 3.2 次要用户

| 用户 | 与本系统相关的一面 | 不作为主用户的原因 |
|---|---|---|
| 有基础的自学者 | 查证、比较、自测 | 学习目标异质，MVP 边界难以界定 |
| 临床从业者 | 快速回溯原文与方剂组成 | 需求偏向即时查证，与学习闭环差异较大 |

### 3.3 首版不服务的角色

中医专家与教师的内容审核职责在首版不承担，该空缺由入库硬检查、抽样校验与冲突上报部分兜底，见 §9.1。

### 3.4 干系人关注点

| 干系人 | 关注点 | 对本文档的输入 |
|---|---|---|
| 主要用户 | 是否可信、能否自测、是否省时间 | 问题优先级、成功标准 |
| 内容维护者 | 导入工作量、关联质量、冲突与缺口处理 | 内容治理约束、优化机会 O-07～O-09 |
| 平台管理员 | 稳定性、权限、缺口与冲突处理链路 | 上报机制的需求来源 |
| 课程评审者 | 问题—需求—设计—测试是否闭合 | 本文档的可追踪性要求 |

### 3.5 用户学习任务

| 编号 | 任务 | 起点 | 终点 |
|---|---|---|---|
| T-01 | 读某篇原文并理解上下文 | 已知篇名或条文片段 | 读到该篇并把握上下文 |
| T-02 | 由方名核对其组成与相关条文 | 已知方名 | 得到组成、出处条文与其他典籍的记载差异 |
| T-03 | 由药味反查相关方剂 | 已知单味药 | 得到包含该药的方剂清单 |
| T-04 | 核对某结论的原文出处 | 已知一句结论 | 得到可点击回溯的原文位置 |
| T-05 | 自测条文记忆与方证对应 | 选定范围 | 得到判定结果与错题回溯入口 |
| T-06 | 由医案回溯所用方与相关条文 | 已知医案或方名 | 得到方剂、条文与出处 |

## 4. 问题陈述

### 4.1 一句话陈述

> 中医经典课程与考试学习者在阅读原文、核对方剂组成、查找出处、验证自身掌握程度时，需要在分散的资料与工具之间来回切换；现有学习平台往往只覆盖阅读、检索或练习中的一段，且结果缺少可核对的原文出处，难以形成可信、连续、可复习的学习闭环。

### 4.2 问题分解

| 编号 | 子问题 | 受影响对象 | 判断状态 |
|---|---|---|---|
| P-01 | 首次进入平台时，不容易理解它能帮助自己完成什么学习任务 | 新访问者 | `[事实]` 教师反馈 |
| P-02 | 阅读、查方、读医案与练习之间缺少连续上下文 | 主要用户 | `[假设]` |
| P-03 | 找到答案后仍需额外确认它来自哪段原文、哪本书、哪一条 | 主要用户 | `[待确认]` |
| P-04 | 练习完成后，错题与相关原文、方剂之间缺少顺畅的复习路径 | 主要用户 | `[假设]` |
| P-05 | 内容维护者难以判断新增典籍、方剂与医案是否被正确组织与关联 | 内容维护者 | `[假设]` |
| P-06 | 平台容易用技术术语表达价值，用户无法判断是否值得使用 | 新访问者 | `[事实]` 教师反馈 |
| P-07 | 库内查不到依据的问题无法回流为内容建设依据，内容缺口不可见 | 主要用户、内容维护者 | `[假设]` |

P-07 是“无依据即拒答”设计的必要条件：若拒答不产生记录，内容缺口将永久不可见。

### 4.3 问题优先级

| 优先级 | 问题 | 理由 |
|---|---|---|
| 高 | P-01、P-06 | 唯一已由外部反馈确认的问题，且改动成本低；不解决则用户无法开始 |
| 高 | P-03 | 在无专家审核条件下，出处是唯一可建立的信任来源 |
| 高 | P-04 | 主要用户的核心任务是自测，练习无回流则闭环不成立 |
| 中 | P-02 | 影响连续性，但需先验证是否真为痛点 |
| 中 | P-05、P-07 | 影响内容可持续性与质量可见性 |
| 低 | P-07 之外的术语门槛 | 可在界面层局部缓解 |

### 4.4 问题与实现缺陷的区分

以下内容不作为本文档的问题来源：框架版本过旧、代码耦合度高、表结构不优雅、部署脚本复杂、开发人力不足。它们只有造成可观察的用户影响时，才转化为问题描述。

## 5. 现有方式的局限

“现有方式”包括四类替代方式，不只指本系统当前形态：

| 编号 | 局限 | 可观察表现 | 证据状态 |
|---|---|---|---|
| L-01 | 产品定位表达不清 | 首屏出现技术术语，访问者无法判断用途 | `[事实]` 教师反馈 |
| L-02 | 技术语言压过学习语言 | 导航与介绍接近开发文档 | `[事实]` 教师反馈 |
| L-03 | 学习任务被拆成多个入口 | 阅读、检索、练习之间需重建上下文 | `[待确认]` |
| L-04 | 学习闭环不显性 | 学完、查完、练完后下一步不清楚 | `[待确认]` |
| L-05 | 出处需用户主动核对 | 能溯源但不容易回到原文 | `[待确认]` |
| L-06 | 内容扩张后治理成本上升 | 关联与审核依赖人工经验 | `[待确认]` |
| L-07 | 存在术语门槛 | 领域词在上手阶段没有解释 | `[待确认]` |
| L-08 | 通用阅读器只有全文搜索 | 无法按药味反查方剂、无法比较两方组成差异 | `[事实]` 功能对比 |
| L-09 | 通用 AI 助手给出无出处结论 | 回答无法回溯到条文，可能生成库内不存在的内容 | `[事实]` 功能对比与公开研究 |
| L-10 | 教材与课程受学期进度约束 | 无法按“当前想核证某条”即时定位，跨书对读不便 | `[假设]` |

### 5.1 电子书方式的实证参照

REF-04 对 22 名研究生的学期制课程观察显示：导航困难 45%、打印或下载困难 36%、界面使用困难 32%、高亮工具难用 32%、调整字号困难 23%；此外存在登录与会话超时、离线访问、跨平台界面不一致、眼睛疲劳等问题，且学生需要明确示范才能发现工具。

该研究样本小、情境为英文研究生课程，不能直接外推为中医学习行为。其可用结论只有一条：**阅读器本身若不降低认知负担，会成为新的障碍来源**，因此阅读体验不能只做“能看”，但也不应作为首版的优先投放方向（见 §7.1）。

### 5.2 证据缺口

| 缺口 | 影响 | 处理 |
|---|---|---|
| 未对真实学习者做任务观察 | P-02、P-04 停留在假设 | 在本文档标注为假设，不作为需求依据 |
| 未实际试用同类产品完成同一任务 | L-03、L-05 的严重程度不明 | 仅保留能力对比结论，不评估体验优劣 |
| 无中医专家评审 | 内容正确性缺少外部背书 | 由入库检查、抽样校验与冲突上报兜底（§9.1） |
| 学生规模数据口径不一致 | 不影响问题定义，影响后续市场判断 | 移交 `docs/02` |

## 6. 项目愿景与成功标准

### 6.1 愿景

> 让中医经典学习者在一个只依赖已导入典籍、每处结论都能回到原文的环境中完成阅读、查证与自测。

### 6.2 产品定位表述

本系统是**以原文和方证关系为准绳的经典学习自测工具**。

不表述为：考试培训机构替代品、押考点工具、中医学全科学习平台、临床决策辅助工具。

### 6.3 成功标准

| 编号 | 目标 | 度量方式 | 目标值 |
|---|---|---|---|
| S-01 | 新访问者能理解平台用途与边界 | 首次访问任务测试：用自己的话说出能做什么、不做什么 | 待基线 |
| S-02 | 用户能完成一次连续学习任务 | 从读到查再到练习的任务完成率 | 待基线 |
| S-03 | 用户能核对内容出处 | 给定问题后找到原文出处的成功率与耗时 | 待基线 |
| S-04 | 练习能转化为复习 | 练习后进入相关原文或错题复习的比例 | 待基线 |
| S-05 | 内容关联可被检查 | 抽样内容的方剂、药味、原文关联正确率 | 待基线 |
| S-06 | 拒答有据且可回流 | 拒答被记录为内容缺口的比例 | 待基线 |
| S-07 | 内容不一致可见 | 抽样冲突样本中被检测出的比例 | 待基线 |

目标值必须在获得基线数据后确定。在基线缺失期间，本表只用于确定“测什么”，不用于判定“是否达标”。

## 7. 优化机会初筛

本节只描述可能改善什么，不确定技术方案。机会的实现方式与成本在 `docs/02` 比较。

| 编号 | 优化机会 | 对应问题 | 优先级 |
|---|---|---|---|
| O-01 | 用学习者语言说明用途、适用人群与不做什么 | P-01、P-06、L-01、L-02 | 高 |
| O-02 | 以“当前学习对象”为上下文锚，贯通读、查、练 | P-02、L-03、L-04 | 中 |
| O-03 | 出处块作为所有输出的统一组成，可点击回溯 | P-03、L-05、L-09 | 高 |
| O-04 | 方证关系检索：方→条文与医案、药→方、类方组成比较 | L-08 | 高 |
| O-05 | 机判练习：题目由结构化数据自动生成，每题可显示依据 | P-04 | 高 |
| O-06 | 错题回到对应原文与方剂 | P-04、L-04 | 中高 |
| O-07 | 无依据问题回流为内容缺口并上报管理员 | P-07 | 中 |
| O-08 | 字段级内容冲突检测、并列展示与上报 | P-05、L-06 | 中 |
| O-09 | 入库硬检查与抽样校验 | P-05、L-06 | 中 |
| O-10 | 术语在首次出现处内联解释 | P-01、L-07 | 低 |
| O-11 | 阅读便捷性：回到上次阅读位置、出处常驻可见、由方名一步跳至原文条文 | P-02、L-03、L-04 | 高 |
| O-12 | 默写比对：凭记忆默写条文或方剂组成，逐字比对库内原文并标出差异位置 | P-04 | 低（首版不做，留作后续优化） |

### 7.1 首版能力投放顺序

1. 检索、出处、方证关系（O-03、O-04）。这三项是练习判据的来源，必须先立。
2. 机判练习与错题回流（O-05、O-06），首版题型为选择题、组成匹配与类方比较。
3. 阅读便捷性（O-11）。
4. 阅读排版打磨（字号、主题、版式等表现层调整）。

说明一：阅读、检索、练习不是三个并列功能，而是同一份结构化数据的三种视图。练习的判定依据就是原文与方剂组成，缺少检索与出处则练习无法出题、无法解释判分理由。因此不存在“先做练习、后补检索”的顺序。

说明二：O-11 与“排版打磨”不同。学习端以手机为主，阅读是主场景，因此 O-11 的三条属首版必须项，且可作为验收条件；字号、主题、版式等表现层调整属打磨项，可在核心能力稳定后进行。

说明三：首版练习只做判据可由枚举与集合运算直接确定的三类题型（选择题、组成匹配、类方比较）。默写比对与条文补全需要对用户自由输入的文本做归一化与容错判定，正确性依赖正字集、异体映射表与差异分类规则，实现与验收成本明显高于结构化题型，故 O-12 与条文补全留作后续优化，首版不做。这一取舍不改变练习的目标，只改变首版的判定方式。

## 8. 系统范围与非目标

### 8.1 内容范围

| 类别 | 是否纳入 | 说明 |
|---|---|---|
| 典籍原文 | 纳入 | 具体书目与底本在导入阶段确定 |
| 以典籍原文为主体的教学整理本 | 纳入（有条件） | 须逐段标注性质：典籍原文／注释／教学论述／医案；**只有标注为“典籍原文”的段落可作为判据与出处**；底本由课程教师指定并授权使用 |
| 方剂组成 | 纳入 | 组成是练习与检索的判据 |
| 医案 | 纳入 | 仅作溯源与检索对象，不作证治推演 |
| 西医基础与临床课程 | 不纳入 | 不在本项目定位内 |
| 典籍之外的医学书 | 不纳入 | 边界不可控 |
| 纯现代教材与讲义（主体为现代论述） | 不纳入 | 主体若非典籍原文，则判据与出处都无从建立 |

### 8.2 书目的认定方式

某部书是否属于本系统的内容范围，不由系统自动判断，也不由提交者单方决定，按下述方式认定：

1. **认定准则**：属于公认的中医经典著作及其注本、校注本；或以典籍原文为主体、逐段可区分原文与论述的教学整理本。主体为现代论述的教材、讲义、期刊论文、科普读物不在范围内。
2. **认定主体**：由管理员依据上述准则判定。
3. **申请方式**：用户可提交书目申请，内容为书名、作者、朝代、版本或出版社、目录、用途说明。**用户不提交文件本体，不触发导入**（见约束 C-08）。
4. **教学整理本的附加要求**：入库前必须完成逐段性质标注，且标注结果需经人工确认；未标注或标注不明的段落不得作为判据与出处。

提交、审核、驳回的具体流程与状态流转由 `docs/03` 规定；本文件只确定“谁认定、依据什么认定”。

### 8.3 功能范围（概念层）

- 典籍原文阅读：按原书段落顺序连续呈现，不做内容重组；配导航树供章节索引；含进度记忆、出处常驻与关联跳转
- 跨书检索：原文、方剂、医案三类对象
- 方证关系检索：方、药、条文、医案之间的既有挂接查询
- 机判练习与复习排程：首版为选择题、组成匹配与类方比较三类，题目由结构化数据生成；错题按间隔逐渐拉长的方式复习，不设永久移出。默写比对与条文补全依赖自由输入的文本容错，留作后续版本
- 基于库内原文的解释与拒答
- 内容缺口上报与内容冲突检测、并列展示
- 收藏、笔记与学习记录
- 官方基础事实数据的查询：方名、别名、组成、药名、性味等可核对事实项，逐条带出处

上述为概念层描述，不构成需求编号；功能需求由 `docs/03` 定义。

### 8.4 外部依赖

| 依赖 | 说明 | 风险 |
|---|---|---|
| 导入底本 | 系统内容全部来自导入，底本质量决定系统上限 | 底本形态不可控将直接影响可导入性，评估见 `docs/02` |
| 方剂与药味词表 | 实体识别与练习判定的依据 | 词表不全将导致漏检 |
| 无外部权威接口 | 首版不依赖第三方知识库实时查询 | 降低不可控性，但也限制了覆盖范围 |

### 8.5 非目标

- 疾病诊断、处方建议、剂量建议（含由系统生成、推荐或换算剂量）；原文与医案正文中已有的剂量按史料原样呈现，不视为剂量建议
- 无出处的中医理论推断
- 病案辨证与处方的自动评分
- 生成新方、替代医师决策
- 医院业务系统与真实患者数据管理
- 与任何院校教材或考试大纲的口径对齐、考点覆盖承诺

### 8.6 端形态与服务对象

| 端 | 承载角色 | 首版是否提供 |
|---|---|---|
| 微信小程序 | 学习者 | 提供，作为主要学习入口 |
| PC Web | 管理员 | 提供，承载书目审核、导入、校对与治理 |
| PC Web | 学习者 | 不提供专属界面；登录后提示使用小程序 |

说明：

1. 账号体系跨端统一。同一账号可在小程序与 PC Web 登录，收藏、笔记、练习记录与阅读进度保持一致。
2. 不提供学习者 PC 专属界面的理由是成本：另做一套学习者 PC 界面会使界面层工作量接近翻倍，而手机更贴合电子书阅读与随身使用。
3. 端形态带来的合规与渲染约束见 `docs/02`；其中域名与备案只在正式发布时构成强制要求，开发与演示阶段可规避。

## 9. 约束与假设

### 9.1 约束

| 编号 | 约束 | 来源 | 后果 |
|---|---|---|---|
| C-01 | 首版无中医教师或高年级学生参与内容审核（首版约束，后续版本引入专家评审） | 用户 2026-11-22、2026-11-23 | 内容正确性缺少外部背书，必须以出处可核、入库硬检查、抽样校验与冲突上报替代；不作为永久设计前提 |
| C-02 | 系统解释只依据已导入内容与官方基础事实数据；两者均无依据即拒答 | 用户 2026-11-22、2026-11-23 | 覆盖率受导入规模与基础事实表完整性限制，会出现拒答；基础事实数据不含判断类内容 |
| C-03 | 练习只做可机器判定题型，题目由结构化数据自动生成 | 用户 2026-11-22 | 病案分析类练习不在范围内 |
| C-04 | 不承诺与教材或考纲口径一致 | D-011 | 不能以“考点覆盖”作为产品价值主张 |
| C-05 | 内容冲突只做检测与并列展示，不做裁决 | 用户 2026-11-22 | 用户可能看到不一致记载，需界面说明 |
| C-06 | 条文定位的版本信息由导入者提供 | 用户 2026-11-22 | 无版本信息的内容无法精确到条号引用 |
| C-07 | 任何输出必须包含书名与篇名；无法提供时不得输出 | 用户 2026-11-23 | 出处是无专家审核条件下的唯一信任来源，属硬约束而非尽力目标 |
| C-08 | 书目导入由管理员独占执行；用户仅可提交书目申请（元信息与目录），可提交的内容不含文件本体，也不能触发导入 | 用户 2026-11-23 | 版权责任与内容质量责任集中于可控角色，避免引入文件上传、内容安全审核与侵权处理机制 |
| C-09 | 学习端为微信小程序，管理端为 PC Web；首版不提供学习者 PC 专属界面；账号跨端统一 | 用户 2026-11-23 | 正式发布需域名与备案，开发与演示阶段可规避；小程序渲染能力受限，阅读器需自行实现 |
| C-10 | 生成式解释默认关闭；启用时由管理员配置单一密钥，用户不配置密钥 | 用户 2026-11-23 | 未配置时退化为只给原文与出处；不采用用户自带密钥 |
| C-11 | 原文显示不改写：段落文本、顺序与标点保持底本原样；错字修正、繁简与异体字统一只作用于检索使用的归一值，并单独留存校勘记录 | 用户 2026-11-24 | 界面默认显示原字；检索使用归一值；两者不一致时可查校勘记录。此约束防止后续为实现功能而改写正文；后续版本若恢复默写比对，判分沿用同一归一值。原文中的剂量随原文原样呈现，按史料处理，不构成剂量建议；展示处须有固定免责声明，且剂量不得由系统生成、推荐、换算或作为检索与解释的答案输出 |

### 9.2 假设

| 编号 | 假设 | 若不成立的影响 |
|---|---|---|
| A-01 | 导入底本为已有整理、带标点的文本或带文字层的 PDF | 若底本为无标点影印件，导入可行性大幅下降 |
| A-02 | 主要用户具备基本文言阅读能力 | 若不具备，术语与解释需求上升，范围扩大 |
| A-03 | 方剂组成在库内可作为判定依据使用 | 若组成记载本身不一致，练习判定需先解决冲突 |
| A-04 | 内容缺口可由管理员通过补充导入解决 | 若缺口长期无法补齐，拒答率居高不下 |
| A-05 | 导入底本不保证覆盖系统定义的全部字段（如条号、版本、证候、剂量） | 缺失字段对应的检索与练习能力需降级或不可用，功能可用范围随底本质量波动；按字段分级处理，不以推断补填 |

### 9.3 已识别风险

| 编号 | 风险 | 影响 | 缓解方向 |
|---|---|---|---|
| RISK-01 | 无专家审核导致内容错误未被发现 | 可信度受损，评审质疑 | 入库硬检查、抽样校验、冲突上报，错误可追溯 |
| RISK-02 | 库内方剂与条文挂接覆盖率不足 | 方证关系检索名不副实 | 导入时统计覆盖率，作为内容建设指标 |
| RISK-03 | 拒答阈值设定不当 | 过松则生成无依据内容，过严则大量拒答 | 阈值需依数据调整，不预先固定 |
| RISK-04 | 选择题的选项设计与判据不严谨 | 出现多个可选答案或“最佳答案”式歧义，机判给出与库内数据不符的结论 | 选项由结构化数据生成，每题恰有一个可由库内数据唯一确定的答案；歧义选项在出题时剔除，不靠人工解释兜底 |
| RISK-05 | 医案证候标注无权威来源 | 按证候检索不可靠 | 降级为按方名与关键词检索，不做证候标准化映射 |
| RISK-06 | 用户任务观察缺失 | 部分问题优先级缺乏实证 | 在文档中标注假设，后续补验 |
| RISK-07 | 判据字段缺失，或解析失败被当作“底本无此项” | 练习与组成比对给出错误结果，或内容质量问题被隐藏至使用阶段才暴露 | 导入结果区分“该有但没有”与“本来就没有”；缺失在界面显式呈现；判据字段缺失的记录不参与出题 |
