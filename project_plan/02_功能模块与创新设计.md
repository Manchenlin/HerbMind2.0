# 02 · 功能模块与创新设计

> 9 大功能模块 + 1 个跨模块基础设施（语料库），覆盖并超越现有系统。标注 **★创新** 的是超越原项目的构想功能。

## 模块总览

| 模块 | 名称 | 一句话 | 优先级 |
|---|---|---|---|
| M1 | 多维智能检索 | 从"翻目录"到"想怎么查就怎么查" | P0 |
| M2 | 方证详情与阅读 | 结构化阅读方证单元 + 条文独立页 | P0 |
| M3 | 练习考核 · 先思后看 | 先想后看 + 自动评分 + 辨证教练 | P0 |
| M4 | 个人中心与学习档案 | 学习闭环：档案/雷达/错题/路径 | P1 |
| M5 | 收藏 · 笔记 · 讨论 | 社区闭环，优质内容回流 | P1 |
| M6 | 知识图谱可视化 | 方-证-药-症 可视化探索 | P1 |
| M7 | AI 智能问答 Agent | LangChain 1.x 多工具 Agent | P0 |
| M8 | 数据治理与科研挖掘 | 治理流转 + 科研统计导出 | P2 |
| M9 | 创新功能集 | 盲盒/加减查证/换算/打卡… | P1~P2 |
| **语料库** | （跨模块基础设施） | **插拔式多语料**：书架 / 切书 / 统一检索 | P0 |

> **语料库（插拔式 · 跨模块）**：平台以同一套骨架适配多类书籍（方证 / 本草 / 药品 / 医案）。用户侧表现为「**书架**」页与**书籍切换器**；系统侧由 `book` / `book_node` / `content_unit` 承载。它不是并列功能，而是**所有模块的地基**——M1 检索、M2 阅读、M6 图谱、M7 Agent 都面向"当前语料 / 全语料"。详见 [14 插拔式书籍扩展方案](14_插拔式书籍扩展方案.md)。

> **用户导入（UGC）**：任何用户都可在「书架 → 导入语料」上传自有资料，填元信息（书名/类型/版权），选解析模板 → 系统自动解析 → 进入**治理审核**（见 M8）→ 通过后上架，可检索 / 问答 / 练习 / 建图。**古籍原文（公版）可自由导入；现代教材 / 题库需授权或仅个人可见。**

## M1 多维智能检索（检索中枢）

**解决问题**：纸质书线性目录 vs 临床复合检索的矛盾。

**三个检索入口**
1. **结构化筛选台 `/search`**：维度 = 经典著作 / 章 / 节 / 类 / 方剂 / 药味 / 证候 / 症状 / 条文 / 页码；任意组合、结果分面统计（如"太阳病 + 含桂枝 + 发热"）。
2. **自然语言语义检索**：一句话（"无汗而喘、脉浮紧用什么方"）→ pgvector 向量 + pg_jieba 全文**混合召回** → 返回方证卡片。
3. **反向索引 `/search/quote-index`**：点条文看"哪些方/案引用它"；点方剂看"书中所有相关案例与条文"。

**★创新**：检索结果**一键「在图谱中展开」**——结果集映射为子图高亮。

---

## M2 方证详情与阅读（内容核心）

**解决问题**：原文无独立详情页、栏目未结构化。

**页面**
- **方剂详情 `/formula/:id`**：组成（药味 + 剂量，可视化"**君臣佐使**"标签）、功效、主治证候、原典出处、相关条文、相关案例、mini 图谱、收藏/笔记/讨论。
- **案例详情 `/case/:id`**：案例一/二/三切换；字段 = 现病史·病情 / 查体 / 辨证 / 立法·治法 / 处方（药味+剂量+用法）/ 治疗效果；按语栏目【提要】【讨论】【证治归纳】【问题】【问题解答】可折叠。
- **条文详情 `/quote/:id`**（**原项目缺失，新增**）：条号、所属经典、原文、引用它的方剂与案例、白话释义（Agent 生成，标注"AI 辅助"）。
- **典籍浏览 `/library`**：经典→章→节→类 目录树，仿古籍阅读。

**★创新**：**渐进阅读模式**——默认只显"原文 + 提要"，其余栏目点击展开，与 M3 打通（未答题时不剧透）。

## M3 练习考核 · 先思后看（学习核心）

**解决问题**：被动灌输；原项目 `is_correct` 恒 null（无评分）。

**页面**
- **练习台 `/train`**：选方证单元；或 **★案例盲盒 `/train/blindbox`** 随机出题。
- **答题面板 `/train/session/:id`**：先给"案例原文"，藏起"辨证/治法/处方/讨论"；用户提交辨证 + 自拟处方。
- 评分报告 `/train/report/:id`：
  - 辨证比对：抽取用户证候关键词 vs 原著证候（LLM 结构化输出 + 证候同义词字典）→ **命中 / 遗漏 / 多余**。
  - 处方比对：药味集合 **F1 值**（重合率 / 加减判定）+ 组合相似度。
  - 总分 = 证 40% + 方 40% + 治法 20%，附**逐条点评 + 原文对照**。
  - **实现（规则兜底）**：药味 / 剂量比对走**确定性规则**（集合运算，非 LLM）；仅"证候语义比对"交 LLM（`temperature=0`）→ **评分稳定、可复现**。

**★创新**
- **AI 辨证教练**：Agent 多轮追问（"有无恶寒？脉象如何？"），逼你补全四诊信息。
- **错题本**自动归集低分单元；**案例盲盒**课堂趣味化。

## M4 个人中心与学习档案（Dashboard）

**解决问题**：原项目无个人中心。

**页面**：`/me` 总览、`/me/profile` 学习档案（**能力雷达**：伤寒/温病/金匮 三经典掌握度）、`/me/wrong` 错题本、`/me/collection` 我的方证库（自建标签/私藏）、`/me/path` 学习路径。

**★创新**
- **学习路径推荐**：基于图谱先修关系（`PREREQUISITE`）+ 薄弱点，推荐下一批方证。
- **成长时间轴**：每掌握一个方证点亮图谱节点，形成个人知识地图。

---

## M5 收藏 · 笔记 · 讨论（社区闭环）

**解决问题**：原项目"有写无读"。

**页面**：`/me/favorites` 收藏夹（按 target 类型分组）、`/me/notes` 我的笔记（锚定到方/案/条/页）、`/discuss` 讨论区（按方证聚合、楼层 + 引用原贴）。

**★创新**：笔记支持 **@方证实体** 生成双向链接；优质讨论被"加精"后回流到方剂详情页"民间心得"区。

---

## M6 知识图谱可视化（Neo4j）

**解决问题**：证-方-症 网络前端未可视化。

**页面**
- **图谱探索 `/graph`**：全屏力导向图，节点 = 方/证/症/药/条/案，边可筛选，点击节点侧栏显属性 + 原文。
- **方心子图 `/graph/formula/:id`**：以某方为中心的邻居子图。

**★创新**
- **方证相似度地图 `/graph/map`**：方剂按药味/证候向量降维（t-SNE/UMAP）到 2D，聚类成"方剂星系"，同类/异治方邻近。
- **跨经典条文关联**：同一方证在《伤寒》《金匮》《温病》横向对照，图中显示"同一方·三经典"路径。
- 多跳查询：如"桂枝汤 → 常见兼证 → 对应加减方"。

## M7 AI 智能问答 Agent（LangChain 1.x · 亮点）

**解决问题**：原项目仅单轮 RAG，无工具、无记忆、无结构化。

**页面**：`/ask` 对话流 + **工具调用轨迹可视化** + 引用卡（点引用跳 M2 原文）+ 右侧联动 mini 图谱。

**能力（多工具 Agent）**：结构化查方/查案/查条文、语义检索、图谱多跳、统计、剂量换算、辨证比对、加减查证、按用户画像个性化。

**★创新**
- **跟诊剧本杀**：Agent 扮"患者"多轮陈述病情 → 你辨证处方 → Agent 扮"带教"点评。
- **歌诀/口诀生成**：按方剂生成记忆口诀。

---

## M8 数据治理与科研挖掘

**治理**：`/admin` 后台——校验状态流转、复核工单、OCR 疑点清单、操作留痕（`verify_log`）。原项目最小实现 → 重构为**完整工单流**。

**科研**：`/research` 工作台——用药频次 Top-N、方证对应统计、时间/经典分布；数据导出（CSV / JSON / GraphML）。

**★创新**：**可复现研究包**——一次分析 = 数据快照 + 图表 + 方法说明，一键导出，便于写论文。
