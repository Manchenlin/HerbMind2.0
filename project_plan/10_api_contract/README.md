# 接口契约（实现期）

本目录是**实现期**的接口契约，不属于 `thinkForProject/` 的课程分析文档。

## 为什么放在这里，不放进 thinkForProject

`thinkForProject/` 里是《软件工程导论》课程的分析与设计产物（`docs/01`～`docs/10`），它们的读者是课程评审，内容按课程方法组织，且必须自成体系——不能依赖实现仓库里的文件，否则课程文档的完整性就没了。

接口契约的读者是写代码的人：字段类型、必填、错误码、示例。这两类东西混在一个目录里，会互相污染：课程文档被实现细节撑大，实现文档被课程术语绕晕，最后谁也说不清哪份是权威。

所以这里单开一个目录，与 `thinkForProject/` 的关系是**派生**关系：契约的骨架从课程设计文档生成，不外挂，也不平行维护。

## 目录内容

| 文件 | 作用 | 能否手改 |
|---|---|---|
| `gen_contract.py` | 生成器：从 `docs/05` §10.3 + 边表投影出骨架 | 是（改生成逻辑） |
| `api_contract.generated.md` | 生成物：51 个方法逐个成节，含覆盖需求与规则约束 | **自动区不能改**；`<!-- HAND:BEGIN … -->` 之间的手写区可以改 |

## 权威边界（重要）

| 内容 | 权威在哪 | 冲突时改哪边 |
|---|---|---|
| 有哪些端点、如何分组、端点职责 | `thinkForProject/docs/05` §10.3 | 改 `docs/05`，再重跑生成器 |
| 每条需求由哪些端点覆盖 | `thinkForProject/track/02_需求到端点.csv` | 改边表 |
| 请求／响应字段、错误码细节 | **`api_contract.generated.md` 的手写区** | 改手写区（`docs/05` 只定义了 3 个关键接口的字段） |
| 端点必须满足的规则类约束 | 边表里 `coverage=rule` 的行 | 改边表 |

一句话：**端点集合听课程文档的，字段细节听这份契约的。** 两条线不交叉，就不会出现"两处都定义同一件事"。

## 用法

```bat
:: 生成 / 重新生成（会保留所有手写区）
python project_plan\10_api_contract\gen_contract.py

:: 检查契约是否与课程文档同步（在需求→端点对账里一起跑）
python thinkForProject\scripts\trace_check.py
```

生成器在文件头写入源哈希（`<!-- SOURCE_HASH: … -->`）。如果 `docs/05` §10.3 或边表改过而契约没重新生成，`trace_check.py` 会报"契约过期"，退出码变 1。

## 与 `project_plan/09_API契约清单.md` 的关系

`09` 是早期手写的契约清单，**不再作为事实源**：它手写维护、与设计文档各自演进，已经无法判断哪边是对的。

本目录的做法是"生成 + 手写分区"：能自动派生的一律派生，只有课程文档本来就没打算写全的部分（字段细节）才手写，且手写区受生成器保护。这样不会再有第二次"两套端点表"。

`09` 文件本身没有删除——删除属红线操作，需明确决定。在正式作废前，请以本目录为准。
