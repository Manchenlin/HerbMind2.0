## 3. ETL 流程

```
【通用古籍导入器（插拔式，见 14 号文档）】
  任意书 docx / 文本
  ├─(0) 注册 book（书名 / 类型 / 版权 / 状态）
  ├─(1) 文本清洗：去重 OCR 双层、剔除坐标数字噪声、去页眉页脚
  ├─(2) 目录解析：按"栏目规则模板"拆 章→节→类→单元 → book_node
  ├─(3) 栏目拆分：【提要】【原文回顾】【案例】【证治归纳】【注意事项】【问题】【问题解答】【讨论】
  ├─(4) 案例拆分：案例一/二/三 → 字段（现病史/查体/辨证/治法/处方/效果）
  ├─(5) 字段解析：正则拆"药名+剂量+单位"；按 book_type 映射到特化表
  └─(6) 结构化结果

结构化结果
  ├─ import_to_pg.py     → 写 PostgreSQL（book/book_node + 特化表 formula/herb/drug/case + quote…）
  ├─ embed_chunks.py     → 生成 content_unit + bge-m3 向量(1024) + pg_jieba 全文列
  └─ build_graph.py      → 按统一本体派生 Neo4j 节点/关系（同名 MERGE 合并），回写 graph_synced
```

> **插拔要点**：「栏目规则模板 + 字段→本体映射」各配一次；之后**加书 = 跑流程，不改表 / 不改码**。

## 4. 各阶段要点

| 阶段 | 输入 | 输出 | 关键处理 |
|---|---|---|---|
| 清洗 | docx 正文 | 去噪文本 | 段落级去重、噪声正则 |
| 层级解析 | 去噪文本 | 章/节/类/单元树 | 标题模式匹配 + 人工校正表 |
| 栏目拆分 | 方证单元 | 结构化字段 | 【】标记切分；无标记时按句式兜底 |
| 案例拆分 | 案例原文 | 案例字段 | "案例一/二/三" + 字段关键词切分 |
| 药味解析 | 组成/剂量 | `formula_herb` | 药名-剂量正则；异体字归一（芎劳→川芎 等） |
| 向量化 | 知识块 | `content_unit.embedding` | bge-m3 云端，1024 维，批量+重试 |
| 建图 | 关系表 | Neo4j | 节点 Merge、关系 Unwind 批量写 |

## 5. 数据治理方案

**校验状态流转**（内容表 `校验状态` + `verify_log`）：

```
待校验 → 已校验（通过）→ 已发布
        ↘ 存疑（→ OCR 疑点 issue → 复核工单 content_review）
```

**治理后台能力**：
- 待复核列表（按章/批次筛选）。
- OCR 疑点清单（如"各等分"漏解析、大小青龙汤缩写、当归芍药散粘连、芎劳/暑察等异体字）。
- 复核工单：认领 → 修改 → 复审 → 通过/驳回，全程 `verify_log` 留痕。
- 操作审计 `audit_log`。

## 6. 已知残留人工项（历史遗留，需治理）

- 大小青龙汤名称缩写未展开；
