## 7. 你的坑（本域专属）

> ### ⚠️ 0. 【会删数据】重跑 `migrate_legacy.py` 会清空 2026-10-26 的药味补录 —— 必须按 4 步顺序补齐
>
> **背景**：源数据（旧库 / `herbmind_data.sql`）里有 **59 个方剂的「组成」段落本来就是空的**，
> `content_unit` 里留下的是字面量 `组成：未找到`。这不是解析 bug，重跑 ETL 也补不出来。
> 域3 已于 2026-10-26 从标准方书**外部补录 54 方 309 味**，数据只存在仓库文件里：
> `database/etl/data/formula_herb_supplement.csv`（另 5 条是章节标题，不补）。
>
> **问题**：`database/etl/migrate_legacy.py` 第 52 行是
> `TRUNCATE relation, content_unit, ..., formula_herb, formula ... CASCADE` ——
> 任何人重跑一次全量迁移，这 309 味补录**连同已回写的正文一起被清掉**，
> 然后 `build_graph.py` 一跑，图库里的 `COMPOSED_OF` 就从 1288 掉回 979，
> 59 个方剂重新变成无药味的孤立节点，问答也答不出「桂枝汤由哪些药组成」。
>
> **正确顺序**（重跑迁移后必须 4 步全做，缺一不可）：
>
> ```bash
> cd database/etl
> python migrate_legacy.py        # 1. 全量迁移（会 TRUNCATE）
> python apply_supplement.py      # 2. 补录 formula_herb（幂等，读上面的 CSV）
> python sync_content_unit.py     # 3. 把药味回写进 content_unit 正文 + 重算这 54 条向量
> python build_graph.py           # 4. 同步 Neo4j
> ```
>
> **第 3 步不能省**：RAG 检索读的是 `content_unit.content`。只补 `formula_herb` 不回写正文，
> 正文里仍是「组成：未找到」，问组成照样答不出来。
>
> **自检**（跑完应为 5，即那 5 个未补的章节标题）：
> ```sql
> SELECT count(*) FROM formula f
>  WHERE NOT EXISTS (SELECT 1 FROM formula_herb fh WHERE fh.formula_id = f.id);
> ```
>
> 细节与踩坑经过见仓库根的 `PROJECT_MEMORY.md` §九（该文件只存本机、不进 git，
> 可让域3 发你），或直接看 `apply_supplement.py` / `sync_content_unit.py` 的模块 docstring。
> 有问题找域3（C）。

1. **pg_jieba 没装** → 走 `jiebacfg (COPY=simple)` 兜底：能建表、能查询，但**中文不分词**（`麻黄汤` 命中 0）。装了才有分词效果（见 `database/pg/00-extensions.sql` 注释）。
2. **生成列 `search_tsv` 别映射到实体** → 插入会报错。
3. **时间用 `OffsetDateTime`**（不是 `LocalDateTime`），否则差 8 小时。
4. JSON 输出用 **camelCase**（`nodeType`），DB 列是 snake_case。
5. 目录**唯一表 `book_node`**——**没有** `book_chapter/section/category`，别去找。
